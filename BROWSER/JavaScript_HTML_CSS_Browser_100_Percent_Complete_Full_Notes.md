# Part 1 --- Web Platform Mental Model

## 1.1 The Three Core Technologies

A browser application is primarily built from:

-   **HTML** --- structure and meaning.
-   **CSS** --- presentation, layout, visual behavior.
-   **JavaScript** --- behavior, computation, interaction,
    communication.

A useful model:


# Final Mental Model

The complete web platform can be understood as:

``` text
                    INTERNET
                       │
                    HTTP/HTTPS
                       │
                    BROWSER
                       │
       ┌───────────────┼────────────────┐
       │               │                │
      HTML            CSS          JavaScript
       │               │                │
       ↓               ↓                ↓
      DOM             CSSOM          JS Runtime
       └───────────────┼────────────────┘
                       │
                 Browser Web APIs
                       │
       ┌───────────────┼────────────────────┐
       │               │                    │
    Network          Storage             Media
       │               │                    │
   Fetch/WS/SSE   IndexedDB/Cache      Audio/Video
       │               │                    │
       ├───────────────┼────────────────────┤
       │
    Workers / Service Workers
       │
    Security / Permissions
       │
    Rendering Pipeline
       │
    Layout → Paint → Composite
       │
      SCREEN
```

## The Most Important Concept

Do not learn HTML, CSS, and JavaScript as three completely separate
subjects.

Learn the **relationships**:

``` text
HTML
  → creates DOM

CSS
  → creates CSS rules/CSSOM
  → styles DOM

JavaScript
  → reads/changes DOM
  → reads/changes styles
  → responds to events
  → communicates with servers
  → uses browser APIs

Browser
  → executes JavaScript
  → parses HTML
  → calculates styles
  → performs layout
  → paints
  → composites
  → enforces security
  → manages storage/network/device APIs
```

That integrated mental model is the foundation for becoming a senior
frontend engineer and understanding the web platform rather than merely
memorizing framework APIs.

# Browser File + PDF Decision Matrix

| Requirement | Preferred browser technique |
|---|---|
| User selects a local file | `<input type="file">` |
| User selects multiple files | `<input type="file" multiple>` |
| Preview selected image | `URL.createObjectURL(file)` |
| Download generated text/data | `Blob` + object URL + `<a download>` |
| Download server PDF | HTTP `Content-Disposition: attachment` |
| Open server PDF | `<a target="_blank">` or `window.open()` |
| Preview server PDF | browser PDF viewer / iframe/object where supported |
| Open generated PDF | Blob/object URL + `window.open()` |
| Generate PDF in browser | PDF-generation library + Blob |
| Print webpage to PDF | `window.print()` + `@media print` |
| Save to chosen local path | File System Access API where supported |
| Large download | Fetch Streams / server streaming |
| Resumable download | HTTP Range + backend support |
| Large upload | multipart/chunk/resumable upload architecture |
| Offline files | IndexedDB + Cache Storage + Service Worker |
| Secure file validation | server-side validation + content inspection |

# Critical Browser Rules for Downloads, Files and PDFs

## Rule 1 — Browser cannot silently read arbitrary local files

The user must select the file or grant access through a supported browser
API.

## Rule 2 — JavaScript cannot universally force automatic download

Browser security and user preferences can control download behavior.

## Rule 3 — Server headers matter

For server-controlled downloads, understand:

```http
Content-Type
Content-Disposition
Content-Length
Content-Encoding
Cache-Control
ETag
Last-Modified
Accept-Ranges
Content-Range
X-Content-Type-Options
```

## Rule 4 — `target="_blank"` is navigation, not a guaranteed PDF viewer

The browser decides how the resource is rendered.

## Rule 5 — `window.open()` may be blocked

Prefer:

```js
button.addEventListener("click", () => {
  window.open(url, "_blank", "noopener");
});
```

because direct user activation is important.

## Rule 6 — Object URLs need cleanup

```js
const url = URL.createObjectURL(blob);

try {
  // use url
} finally {
  URL.revokeObjectURL(url);
}
```

For a new tab, lifetime handling must account for the fact that the new
document may still need the object URL.

## Rule 7 — PDF generation is not a core ECMAScript feature

The browser provides binary/file/network/printing primitives. PDF
generation itself is normally supplied by a server or a PDF library.

## Rule 8 — Client-side validation is not security

Always validate authorization and uploaded content on the server.
